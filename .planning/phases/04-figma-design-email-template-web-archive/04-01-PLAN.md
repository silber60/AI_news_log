## Phase Goal

**As a** subscriber, **I want to** open any issue on the web from the email, browse past issues on one site, and leave the list with one confirmed click, **so that** the newsletter feels like a real brand I can read anywhere and stop whenever I like.

<objective>
Tracer slice for the web archive: on a mode=send run, the issue is published to GitHub Pages at its fixed URL, the home page lists it under the archive anchor, and every email's 웹에서 보기 / 지난 호 보기 links point there.

Purpose: Proves the whole path (send → publish job → commit → Pages deploy → live URL linked from the email) before any design work. Research finding 1: GITHUB_TOKEN pushes never trigger a branch Pages build, so the deploy path must be proven first.
Output: newsletter/web.py, `publish` and `site` CLI commands, render.SITE_URL / issue_url / render_web_issue, minimal home template, merged publish + deploy-pages jobs, pages.yml, committed docs/index.html, owner-switched Pages source.

Tracer note: Tasks 2 and 3 together are the phase tracer (one path: email link → publish → deploy → live page). They are `type="auto"`; Task 2 proves the code path locally end to end, Task 3 wires the same path into Actions, and Task 4 proves it live.
</objective>
