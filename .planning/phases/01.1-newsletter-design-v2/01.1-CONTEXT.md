**Gathered:** 2026-11-02 (from the Figma design session after the first live preview run)
**Status:** Ready for planning

<domain>
## Phase Boundary

The email built by the Phase 1 pipeline is restyled to the owner-approved Figma v2 draft. Each Top 10 card now describes the model (one-line summary, 3-line summary, model info table) instead of listing 활용 아이디어. The `Issue` schema moves to v2 to carry the new fields. The subject becomes a headline about the week's top topic.

Not in this phase: content for the 이번 주 바로 써볼 만한 것 / 흐름 / AI 기술 쉽게 보기 sections (Phase 3 fills them; this phase only renders their slots and skips them when empty), code-decided verdict values (Phase 2), Naver/Gmail rendering sign-off and the web archive (Phase 4), cron (Phase 5).

</domain>

## Implementation Decisions

### Design source
- **D-01:** The Figma frame `Newsletter / Web 640 (draft)` (file `qyJcGii2MLHTbi4W9mPZkx`, node `7:22`) is the layout source of truth, including the owner's own alignment edits. The card layout is the component `Card / Top10 item` (node `7:2`). Read both with Figma tools before writing the template. — **Reversibility:** reversible
- **D-02:** References the owner gave: NEWNEEK (`whatsup@newneek.co`) and 어세스타 성장레터 (`newsletter@assesta.com`) emails. Palette: orange accent `#FF6B00` with light orange boxes `#FFF6F0`, navy `#303A83` with light blue `#EDF6FF` for the explainer, text `#222222`, gray `#7F7F7F`. Font: system Korean stack in the email (Figma used Noto Sans KR only because no other Korean font was available there).

### Section order
- **D-03:** Top banner (해달) → header (hashtags, date, 웹에서 보기, brand) → issue headline + hero image → personalized greeting → 이번 주 바로 써볼 만한 것 (tool otter) → 이번 주 흐름 한눈에 → "이것만 보면 끝! 이번 주 AI 모델 Top 3 ⚡️" (magnifier otter) with ranks 1-3 → AI 기술 쉽게 보기 🔍 (chalkboard otter) → "놓치기 아까운 4위부터 10위까지 👀" with ranks 4-10 → closing line "이번 주 브리프는 여기까지! 다음 주 월요일에 또 만나요 👋" + waving-otter banner (인사해달) → footer.
- **D-04:** Sections whose Phase 3 content is not available yet (highlight, trend, explainer) are omitted from the rendered email, not shown empty.

### Card content
- **D-05:** Card order: optional model image (max 1) → `N위 ㅣ 유형 ㅣ ▲ upvotes` → Korean title (model names / AI terms in English) → English original title → **bold one-line summary** (existing 한줄 요약, ≤ ~80 chars) → **3-line summary** (what it does, what is new vs. before, reported result) → **🧩 모델 정보** table → badges → links.
- **D-06:** 활용 아이디어 is removed from the email and from the Claude output contract (ANLY-03 amended).
- **D-07:** 모델 정보 rows: 유형, 구조, 크기, 학습 데이터, 공개 범위. 유형 and 구조 are written by Claude from the abstract/project page. 크기, 학습 데이터 and 공개 범위 are facts: code fills them from HF/GitHub evidence when available, otherwise `확인 필요`. Claude never guesses them (project hard rule). Phase 2 evidence work will fill more of them.
- **D-08:** The 3-line summary follows the humanizer core subset and the English-terms rule from Phase 1 (D-05 of Phase 1).

### Images
- **D-09:** Five otter images are in the Figma file: 해달 1 (top banner, `264ff8a7…`), 공구_해달 (tool, transparent), 돋보기_해달 (magnifier, transparent), 칠판해달 (chalkboard, transparent), 인사해달 (closing banner). Export them, compress (target ≤ 200 KB each), commit under a public path, and serve via a public HTTPS URL (GitHub Pages or raw.githubusercontent). Every `<img>` has alt text and explicit width/height.
- **D-10:** Transparent otters are large section decorations (~150-170px in the 640 design), right of the section title.
- **D-11:** Per-item model image: at most one, only when a usable image URL exists in HF data (researcher to find the field); otherwise the card has no image block. Never embed images as base64.

### Subject and attribution
- **D-12:** Subject is a headline-style line about the week's top topic, like the references (e.g. "🤖 말만 하면 로봇이 움직인다? 이번 주 AI 모델 10"); no fixed `[AI 주간 모델 브리프]` prefix. Test mode keeps the `[TEST] ` prefix. This replaces Phase 1 D-01. Sender display name stays "AI 주간 모델 브리프".
- **D-13:** The email must not say it is AI- or auto-generated and must not name Claude. Remove the footer line "이 메일은 자동으로 생성되었습니다." Footer keeps 출처: Hugging Face Papers, the 수신거부 line and 웹에서 보기 · 지난 호 보기.

### Schema
- **D-14:** `Issue` schema v2: add per-item 3-line summary, 유형/구조 strings, 크기/학습 데이터/공개 범위 fact fields (default `확인 필요`), optional item image URL, and an issue-level headline string for the subject/hero. Remove or deprecate `use_ideas_ko`. Commit `schema/issue.schema.v2.json` with the same drift test pattern; migrate fixtures. — **Reversibility:** one-way — `Issue` is the frozen contract every later phase fills; v2 must be confirmed before the snapshot is committed.

### Claude's Discretion
- Exact pixel spacing/font sizes when translating Figma to table HTML, image export sizes, the headline wording rules (length cap, emoji use), how to skip empty sections in Jinja.

</decisions>
