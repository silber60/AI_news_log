## Summary

Three findings change how the plan should look.

1. **The exported "transparent" otters are not transparent.** All three 400×400 PNGs have alpha extrema `(255, 255)` and an opaque `(30, 30, 30)` background, which is the Figma dark canvas baked into the export. On `#FFF6F0` / `#FFFFFF` / `#EDF6FF` sections they would show as dark squares. A border flood-fill key (threshold 12) removes the background cleanly; I checked the result visually on the section colors. The resulting files are 20-26 KB as palette PNGs with real alpha. A clean re-export from Figma is still better if the owner can do it.
2. **For the per-item image, use `paper.mediaUrls`, not `thumbnail`.** `thumbnail` (and the page `og:image`) exists for 10/10 papers, but it is a 1200×648 render of PDF page 1 (title, authors, abstract). Ten of those would look like ten gray paper scans. `mediaUrls` holds images that authors uploaded (teaser or architecture figures). In W44 the Top 10 has **1/10** usable image (rank 1, PNG). Five are `.mp4` only (unusable in email) and four have nothing. Week-wide it is 40/214 (19%). So most cards will have no image, which D-11 allows.
3. **Most fact fields will read `확인 필요` this week.** One `GET /api/papers/{id}` per item returns `linkedModels`, `linkedDatasets`, `linkedSpaces` and `githubRepo`. Only 2/10 W44 papers link a model, and none of those 3 models carries `safetensors` metadata. Coverage: 크기 0/10, 학습 데이터 1/10 (`cardData.datasets`), 공개 범위 6/10. This is a small slice of EVID-01. Build it as `newsletter/stages/enrich.py` so Phase 2 extends it instead of rewriting it.

**Primary recommendation:** Ship Issue v2 with a `ModelInfo` sub-model (Claude strings plus code fact strings defaulting to `확인 필요`), an optional `ItemImage(url, width, height)` restricted to the `cdn-uploads.huggingface.co` host, and a required `headline_ko`. Add a non-fatal `enrich` stage (≤ 20 HF GETs plus ≤ 10 ranged image GETs). Add one headline Claude call with a code-chosen fallback. Rewrite the template from section macros, each tagged `data-section`, so ordering and skipping are testable. Host otter assets at `docs/assets/email/v1/` behind one `ASSET_BASE_URL` constant.

## Headline (D-12, DLVR-07)

**Recommendation: one extra Claude call after `analyze_items`. Claude writes the hook text and picks the emoji from a closed enum; code assembles the line.**

- Input (`<items>` fence, URL-stripped like `paper_block`): ranks 1-3 `title_ko`, `ai_type`, `summary_ko`, `does_ko`. These are already-validated Claude strings plus code enums, so no new untrusted data enters the call.

- `<div>`, `class=`, a surviving `<style>`, background images, SVG, base64 images: existing tests forbid the first three. Keep those assertions, but **relax `"<img" not in out`** to the new img asserts.

## Common Pitfalls

### Pitfall 1: The otter "transparent" exports are opaque dark squares
**What goes wrong:** the tool, magnifier and chalkboard PNGs have alpha `(255,255)` and background `(30,30,30)`; the spec's "400×400 transparent" is wrong. [VERIFIED: Pillow `getextrema`, corner pixels, visual check]
**How to avoid:** ask the owner to re-export from Figma with a transparent background. Otherwise key the background with a border flood-fill (verified clean on `#FFF6F0` and `#EDF6FF`). A test asserts `Image.open(asset).getchannel("A").getextrema()[0] == 0` for the 3 otters.

### Pitfall 2: Treating `linkedDatasets` as training data
Paper-linked datasets include eval benchmarks (`tencent/Hy-Nomas-Bench`). Only the model card's `cardData.datasets` / `dataset:` tags declare training data. Otherwise `확인 필요`.

### Pitfall 3: Absence written as a negative fact
No linked model does not mean "가중치 비공개". Store `None`, not `False`, in `poc.has_*`, and render `확인 필요`.

### Pitfall 4: respx `assert_all_mocked=True` breaks every `run_build` test
`test_render._build`, `test_e2e`, `test_analyze`, `test_fetch` (W53), `test_select` and `test_cli` call `run_build` under respx. New `api/papers`, `api/models` and `cdn-uploads` requests are unmocked, so `AllMockedAssertionError` is raised. It is an `AssertionError`, so enrich's `except httpx.HTTPError` will not swallow it. Add a shared conftest helper that registers the enrich routes from the new fixtures. Also keep a test where every enrich route returns 500, so the build still succeeds with all `확인 필요` (proves non-fatal).

### Pitfall 5: "No AI wording" test vs legitimate "Claude"
D-13 bans authorship claims, but Figma badges say `Claude/GPT` and Phase 3 tags say `Claude Skill`. A blanket `"Claude" not in html` test breaks in Phase 2/3. Test authorship phrases instead: `자동으로 생성`, `자동 생성`, `자동으로 작성`, `AI가 작성`, `AI가 생성`, `AI가 만든`, `Claude가`, `Claude로`, `generated`. Keep a separate 1.1-only assert that `Claude` is absent while all `claude_gpt` verdicts are `확인 필요`.

### Pitfall 6: Size headroom for Phase 3
The prototype worst case is **76,568 B** (10 images, code+project links on all cards, 70-char summaries, 55-60-char lines, long info values), about **7.2 KB per card**. That leaves ~15 KB for the highlight/trend/explainer sections. The font-stack declaration is 124 B and repeats on ~13 text cells per card (~16 KB total). If Phase 3 overflows, shorten the stack (drop the duplicate `'맑은 고딕'`) before restructuring. [VERIFIED: prototype rendered through css_inline with the real `FONT_STACK`]

### Pitfall 7: Badges full of `확인 필요`
In 1.1 every verdict is still `확인 필요`. Three gray pills per card × 10 adds noise and contradicts the "reads fine" goal. Recommend rendering a badge only when its verdict ≠ `확인 필요`, so none show in 1.1 and Phase 2 lights them up. [ASSUMED: owner preference; flag in plan]

### Pitfall 8: Duplicate rank-1 image
The hero uses the rank-1 image (576×300 in Figma) and card 1 would show it again. Recommend: when the hero shows it, card 1 omits its image block. [ASSUMED: owner preference]

### Pitfall 9: Header date in UTC
"2026.11.02 월요일" = `issue.week_end + 1 day` (KST week math, already in `newsletter/week.py`). Never use `date.today()` on the runner.

### Pitfall 10: Existing tests tied to v1
These must be rewritten, not deleted silently: `test_schema.py` (snapshot path, `schema_version == 1`, `test_three_ideas_rejected_zero_accepted`), `test_render.py` (`"<img" not in out`, `#{rank}<` and `▲ {upvotes}<` markers, ideas tests, the 4 subject tests, explainer/trend not rendered, `"확인 필요" not in out`), `test_analyze.py` (ideas checks lines 163-318), `test_e2e.py:98` (field set), `test_prompt.py:58` (`prompt-version: 2`). Baseline today: 164 tests pass. [VERIFIED: `uv run --frozen pytest -q`]

### Image dimensions from a ranged GET

from io import BytesIO
from PIL import Image

def image_dims(client, url: str) -> tuple[int, int] | None:
    r = client.get(url, headers={"Range": "bytes=0-65535"}, timeout=15)
    if r.status_code not in (200, 206) or r.headers.get("content-type") not in {"image/png", "image/jpeg", "image/gif"}:
        return None
    try:
        return Image.open(BytesIO(r.content)).size   # header only; no full decode
    except Exception:
        return None

## Security Domain

| ASVS | Applies | Control |
|------|---------|---------|
| V5 Input validation | yes | HF strings are untrusted: Jinja autoescape stays on; dataset/model IDs are length-capped and URL-stripped; `HttpsUrl` + `cdn-uploads` host allowlist for images; `extra="forbid"` on Claude output |
| V7 Logging | yes | enrich/headline logs carry codes and counts only; no response bodies, no model text |
| V2/V3/V4/V6 | no | No auth or crypto changes |

| Threat | STRIDE | Mitigation |
|---|---|---|
| Tracking pixel / hostile image host via `mediaUrls` | Info disclosure | Host allowlist `https://cdn-uploads.huggingface.co/` |
| Prompt injection via titles into the headline call | Tampering | Input is already-validated Claude strings, fenced; output closed enum + length/char checks + fallback |
| Header injection via headline | Tampering | `_one_line` + CR/LF strip in `build_subject` (existing guard) |
| Decompression bomb on image header read | DoS | Header-only `Image.open` on ≤ 64 KB; catch all exceptions → no image |
| Asset URL rot breaking sent mails | Availability | Versioned `v1/` path, never overwrite |
