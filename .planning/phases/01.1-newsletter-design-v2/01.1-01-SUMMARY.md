# Phase 1.1 Plan 01: Issue Schema v2 and Model Detail Fields Summary

Issue contract moved to v2. It adds `headline_ko`, three summary lines per item, a code-guarded `ModelInfo` (facts default to 확인 필요) and an optional item image limited to the HF CDN. Claude output, prompt v3, the card and the text part all carry the new fields. The owner-requested optional `Explainer.image` is included.

## Task 1: Owner decision (recorded verbatim)

option-b: add optional Explainer.image (ItemImage | None, same host rule, code-filled)

Full owner message, as relayed by the orchestrator: "Approve the field list as you proposed it, with one addition: an optional `image: ItemImage | None = None` on Explainer, using the same ItemImage type and the same `https://cdn-uploads.huggingface.co/` host rule. It is filled only by code, with the related item's model image when one exists (Phase 3); otherwise it is None. Everything else stays exactly as your table shows."

`schema/issue.schema.v2.json` did not exist before this answer. It was generated and committed in Task 2 (cbb183e).

## What was built

- **Schema v2** (`newsletter/schema.py`):
  - `SCHEMA_VERSION = 2`, `UNKNOWN`, `IMAGE_HOST`.
  - `ItemImage`: https only, must be on `cdn-uploads.huggingface.co/`, width and height > 0.
  - `ModelInfo`: kind_ko and architecture_ko come from Claude. size, training_data and release default to UNKNOWN. Also has an evidence list.
  - `Item`: adds `summary_lines_ko` (exactly 3 non-empty lines), `model_info` and `image`. `use_ideas_ko` and its validator are removed.
  - `Issue`: adds `headline_ko` and `schema_version: Literal[2]`.
  - `Explainer`: adds `point_ko`, `example_ko` and `image`.
  - `HfPaper` adds `mediaUrls`. `ItemAnalysisLLM` now has 8 fields. New: `HeadlineEmoji` and `HeadlineLLM`.
  - The v1 snapshot is kept as history.
- **Analysis**:
  - `normalize` runs one-line normalization on all 7 text fields.
  - `to_item` builds `summary_lines_ko=[does, new, result]` and `ModelInfo(kind, architecture)`. It leaves the fact fields at their UNKNOWN defaults.
  - New caps: `LINE_LIMIT` 70, `KIND_LIMIT` 30 and `ARCH_LIMIT` 60. New codes: `line_len`, `line_empty`, `kind_len`, `kind_empty` and `arch_len`.
  - If only length codes are left after the retry, each field over its limit is trimmed. Any other code still raises `AnalysisInvalid`.
- **Prompt v3**:
  - Five new field sections. It says 크기 / 학습 데이터 / 공개 범위 are filled by code. It requires exactly "확인 필요" for an unknown architecture.
  - The ideas section is removed. The humanizer wording now says 모든 필드 / 3줄 요약.
- **Headline**:
  - `fallback_headline(items)` returns e.g. "🧠 PDRVLA 등 이번 주 AI 모델 10" (" 등" is dropped when n == 1).
  - `run_build` passes it to `Issue`. `build_subject` is not changed (plan 04 switches it).
- **Card** (template-version 3):
  - Bold one-liner, then three "· " lines joined with `<br>`.
  - A nested "🧩 모델 정보" table with 5 rows: 유형, 구조, 크기, 학습 데이터, 공개 범위. The text part has the same content.
- **Fixture**:
  - `issue_w44.json` migrated with a one-off scratchpad script (not committed).
  - Rank 3: training_data and release "가중치 · GitHub · 데모". Rank 4: release "가중치 · GitHub · 데모". Other items with a GitHub link: release "GitHub". Everything else: 확인 필요.
- **Rank-1 image URL source: live.** `https://cdn-uploads.huggingface.co/production/uploads/6415947858a690df103af49f/TdENf5Pa8C0iPVuP164gl.png` (mediaUrls[0] from `api/papers/2610.37381`), 576×234.
- **Test helper**: `mock_hf_week(router, pages, issue_id)` in conftest. All run_build call sites in render, e2e, analyze, select and cli use it.
