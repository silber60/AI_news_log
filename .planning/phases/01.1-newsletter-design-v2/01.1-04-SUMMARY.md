# Phase 1.1 Plan 04: Figma v2 email template Summary

The email now follows the Figma v2 draft. It has 11 `data-section` rows in this order: banner, header, hero, greeting, highlight, trend, top3, explainer, rest, closing, footer. Hosted otter images come from `ASSET_BASE_URL`. Cards are split into a Top 3 group and a 4-10 group, and each card has the 🧩 모델 정보 box. The highlight, trend and explainer sections render only when they have data. The subject is now `issue.headline_ko`. Neither the HTML, the text part nor the subject mentions AI or automatic writing.

## Byte sizes

| Render | Bytes | Limit |
|---|---:|---:|
| W44 fixture `email.html` | **57,779** | 92,160 |
| Worst case (plan spec) | **87,105** | 92,160 |

- The worst case uses 10 images at 576×260 (rank 1 is also the hero), code and project links on every card, and an 80-char summary_ko. Each item also gets 70-char lines and a 30-char kind / 60-char architecture. Facts are at the enrich bounds, and there are 3 highlights, a 300-char trend and an explainer with point, an 800-char body and an example.
- Before the font-stack trim, the plan-spec worst case was 90,436 B.
- **Headroom warning for Phase 2.** Badges appear once verdicts are known, and with all three filled on every card the same worst case is about **93,845 B**, over the limit. With 60-char Korean and 150-char English titles it is about 97 KB. Each card spends ~2.1 KB on the font stack (18 cells × 115 B). The next lever is dropping `BlinkMacSystemFont` and/or `-apple-system`, which saves ~35 B × ~215 cells ≈ 7.5 KB. I did not make that change here because it is a font decision that goes beyond the step the plan allowed.

## Deviations from Plan

1. **[Rule 1 - test update] Affiliation tests moved to Task 1.** The Task 1 card already dropped the affiliation row and line. So `test_affiliation_row_only_when_present` became `test_affiliation_not_rendered_in_html`, and the text-part affiliation check was removed in Task 1 instead of Task 2 (c9395bb).
2. **[Rule 1] Worst-case test scope.** My first worst case also had 80-char Korean titles, 180-char English titles and all verdicts known, which gave 107,079 B. The plan's worst-case spec has none of these, so the test now follows the spec (87,105 B). The badge case is recorded above as a Phase 2 headroom warning.
3. **[Rule 3] Pill markup.** Pills are inline `<span>`s in one font-stack cell instead of one td per pill with spacer cells (Pattern 3). This saves ~400 B per card. It renders the same in Chrome, and Outlook shows square corners, as before.
4. **Closing banner** sits inside `data-section="closing"`, so the order test sees exactly 11 sections.
5. **Verify path.** The plan's `<automated>` commands `cd` into the main checkout. They were run in the worktree instead, as instructed.
