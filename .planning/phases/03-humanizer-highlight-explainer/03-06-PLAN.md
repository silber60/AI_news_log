In humanize.py add `polish_issue(issue, client) -> Issue`, following research §2 in this order:
1. Apply cleanup to every collected field (sentence and name kinds) and rebuild the Issue.
2. Lint the sentence fields. If none needs_polish, skip the call.
3. Otherwise send one `analyze._request(..., system=polish_system_prompt(), output_format=PolishLLM)`. The user content is a `<fields>` block holding only the flagged fields, each as `id`, `kind: 문장`, `limit`, `problems` and `text` lines.

5. Set accepted texts by path on the cleaned dump and rebuild with Issue.model_validate.
6. Diff guard: flatten the before and after dumps to leaf paths. If any leaf outside the accepted ids differs, or the key sets differ, discard all fixes and log `polish=discarded reason=diff`.
7. Re-lint. Log `humanizer=unfixed fields=<n> codes=<sorted codes>` when fields are still flagged.
8. Apply dash_fallback to every collected field, logging `cleanup=dash fields=<n>`.
9. Check that the final dump differs from the original only at collected paths.
