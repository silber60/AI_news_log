This is the first time the workflow can write to the repo. It pulls a small part of Phase 5's commit-back forward (D-06). The Build step reads `${{ github.token }}`, so the write scope cannot go on the run job. GitHub has no step-level permissions. The job is added after the run job, exactly as follows:

```yaml
  record-topic:
    needs: run
    if: ${{ inputs.mode == 'send' && github.ref == 'refs/heads/main' && needs.run.result == 'success' }}
    runs-on: ubuntu-latest
    timeout-minutes: 10
    # The only job with a write-scoped token: it commits data/explainer_topics.json after a send (D-06, D-15).
    permissions:
      contents: write
    env:
      MODE: ${{ inputs.mode }}
      PYTHONUNBUFFERED: "1"
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1  # v7.0.1
        with:
          persist-credentials: false
      - uses: astral-sh/setup-uv@68559e99cc807c1eb7e9238fd43a15bba460eec2  # v10.3.3
        with:
          python-version: "3.14"
          enable-cache: true
      - name: Install locked dependencies (record)
        run: uv sync --frozen
      - uses: actions/download-artifact@9000827ccba6bdab643e8b6fd33ac0654aef8333  # v8.0.2
        with:
          name: issue-${{ github.run_id }}
          path: archive/
      - name: Append explainer topic
        run: uv run python -m newsletter record-topic --mode "$MODE"
      - name: Commit topic record
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          git diff --quiet -- data/explainer_topics.json && exit 0
          # identity is needed by both the commit and the rebase in the retry loop
          git config user.name silber60
          git config user.email 81203897+silber60@users.noreply.github.com
          git commit -m "chore(data): record explainer topic" -- data/explainer_topics.json
          for i in 1 2; do
            git pull --rebase "https://x-access-token:${GH_TOKEN}@github.com/${GITHUB_REPOSITORY}.git" main \
              && git push "https://x-access-token:${GH_TOKEN}@github.com/${GITHUB_REPOSITORY}.git" HEAD:main && exit 0
          done
          exit 1
```

How the job is limited:
- It runs only for mode=send on main, after the run job succeeds. Preview and test never start it, and the CLI also refuses to write outside send mode.
- It reads no secret. The token is only in the last step's env. The checkout does not persist credentials.
- The data commit does not trigger CI. Commits pushed with GITHUB_TOKEN start no workflow runs.
- If the job fails, the mail has already gone out, so a red job is the only signal. The cost is that next week's explainer might repeat this topic. To recover, re-run only this job. It writes nothing if the topic is already recorded.

Before the first send, check these:
- Is main branch-protected? A protected main rejects the push.
- download-artifact v8 must read artifacts from upload-artifact v7 (A4, not verified).
- The token-in-URL push is assumed to work (A5).
