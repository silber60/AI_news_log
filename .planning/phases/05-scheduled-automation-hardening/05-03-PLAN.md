## Phase Goal

**As the** newsletter owner, **I want** the issue to reach subscribers every Monday 08:00 KST with nobody touching it, re-runs to be safe, and a report of every outcome, **so that** I never have to press send and never double-mail or late-mail a reader.

<objective>
The committed send ledger (DLVR-05): a keyed hash per mailed reader per week, written after every successful message and committed even when the run fails, so no re-run ever mails the same issue twice to the same person.

Purpose: D-05. 05-01 already uploads data/ledger/ with always() and commits it from the always-run publish job on the branch tip, so this plan only has to write the right file at the right moment.
Output: newsletter/ledger.py, the on_sent hook in send.py, the skip and write path in deliver.py, tests/test_ledger.py, a test-wide NEWSLETTER_LEDGER_DIR redirect.

Coordination: Phase 4.2 owns the connection code in newsletter/delivery/send.py (host, port, login, From/Reply-To). This plan only adds the keyword argument on_sent to send_messages and one call after each successful message, inside whatever loop 4.2 left, keeping its error handling (DeliveryError with class name and code only). If 4.2 replaced send_messages with another per-message sender, add the same hook there and record it in the SUMMARY.
Runs in parallel with 05-02 (checkpoints); no shared files.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-11 | Information disclosure | membership test on a public ledger | high | mitigate | HMAC-SHA256 keyed with UNSUBSCRIBE_TOKEN_SECRET and the ledger-v1: domain prefix (owner A1); no plain hash, no address, sorted keys hide order |
| T-05-12 | Tampering / DoS | mass unsubscribe through leaked tokens | high | mitigate | The ledger never stores unsubscribe tokens; test asserts key != token |
| T-05-13 | Repudiation / abuse | duplicate mail on re-run | high | mitigate | Write after each message, always() upload and commit (05-01), tip checkout, skip filter; a mismatched ledger file fails closed |
| T-05-14 | Information disclosure | logs | medium | mitigate | Counts only; caplog test for addresses and 64-hex keys |
| T-05-15 | Repudiation | runner killed before the always() upload | low | accept | That attempt's progress can be lost and a few readers re-mailed; acceptable for a small list (research Pattern 6 residual risk) |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No installs; stdlib hmac and hashlib only |
