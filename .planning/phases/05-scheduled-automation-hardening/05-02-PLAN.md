## Phase Goal

**As the** newsletter owner, **I want** the issue to reach subscribers every Monday 08:00 KST with nobody touching it, re-runs to be safe, and a report of every outcome, **so that** I never have to press send and never double-mail or late-mail a reader.

<objective>
Per-stage checkpoints in archive/<week>/ so the 08:00 send reuses the 06:00 build and any re-run of a week costs no new HF fetch and no new Claude billing, with --force-stage as the deliberate way to redo a stage.

Purpose: D-04 and AUTO-05. 05-01 already commits archive/ back after every test or send run and checks out the branch tip, so these files are what the next run finds.
Output: checkpoint IO in store.py, the stage loop in pipeline.py, build --force-stage, the force_stage dispatch input, tests/test_checkpoints.py, and existing double-build tests adjusted.

Runs in parallel with 05-03 (ledger). This plan does not touch newsletter/delivery/, tests/conftest.py or the ledger.
</objective>
