## What changed

- **enrich.py:**
  - New constants: `RATIO_MIN, RATIO_MAX = 1.2, 4.0`, `IMAGE_MAX_TOTAL_BYTES = 1_000_000`, `MAX_PROBES = 6`, `RAW_BASE`, `README_MAX_BYTES = 262144` and `GITHUB_REPO_RE`.
  - `hf_image_urls` returns every HF image candidate. `pick_image_url` stays the first-of wrapper.
  - New functions: `parse_repo`, `readme_candidates` and `_read_readme`. `_read_readme` streams the README with `follow_redirects=False`.
  - `_read_head` now uses `follow_redirects=False`. A 3xx gives `redirect`. The total comes from `content-range` on a 206 or `content-length` on a 200. An over-cap total gives `bytes`, and an unknown total gives `bytes_unknown`.
  - `_Prober` shares the 6-probe budget across HF and README candidates.
  - `pick_image(client, media, rank, github_url)` reads `githubRepo` from the HfEntry in `enrich_items`.
- **Candidate rules:**
  - HTML comments and fenced code blocks (``` and ~~~) are dropped first.
  - Markdown and `<img>` sources are read in document order, then `html.unescape`d.
  - `//` sources get `https:`. `http://`, `..`, `?` and `#` are rejected.
  - github.com `blob` and `raw` links are rewritten to raw.githubusercontent.com.
  - Relative, `/` and `./` paths resolve to `HEAD`.
  - Only png, jpg, jpeg and gif pass, matched case-insensitively.
  - Badge patterns are rejected, and so are logo-like file names.
  - Redirecting or expiring hosts are rejected by name: user-attachments, repo `/assets/`, HF `resolve`, private-user-images and camo. After all that, the IMAGE_HOSTS allowlist and the 300-character limit still apply.
- **conftest:**
  - `mock_github(router, readmes=None, images=None, *, fail=False)` serves README text and Pillow images with the captured size, type and `content-range` total. Unknown paths get 404.
  - `mock_enrich` registers it as `routes["github"]` and passes `fail`, `readmes` and `readme_images` through.
  - `partial(body, ctype, total)` is a new helper.
  - The default CDN answer now carries a content-range.
  - `image_bytes` is `lru_cache`d.
- **Tests:**
  - test_e2e asserts the facts for all 10 star ranks.
  - test_enrich has the W44 README-image build test. The old rank-1 HF test now also checks that rank 1's README is never requested.
  - test_hf_fixtures covers both Top 10 sets, plus a guard on readme_w44.json: no email shapes (retina names allowed), no avatars, and image tags only.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Probe policy moved into Task 1**
- **Found during:** Task 1
- **Issue:** The tracer's expected ranks (5, 6, 8, 9) need the 1 MB cap and the ratio floor of 1.2. Under the old 1.3-3.5 bounds RoboHarness fails, and without the cap rank 5 would take the 7.6 MB GIF.
- **Fix:** `IMAGE_MAX_TOTAL_BYTES`, the redirect rule, the ratio and `MAX_PROBES` shipped in f645620. In the same commit, test_square_ratio_lower_bound moved to 1.2, and `_resp` gained a content-range. Task 3 added the boundary and fall-through tests.
- **TDD note:** the Task 3 behavior tests all passed on their first run, so there was no RED phase. Task 2 did have a real RED: 11 of 52 cases failed before the rules were completed.

**2. [Rule 1 - Test] Empty-body decode case**
- An empty 206 cannot carry a valid content-range, so the old `decode` case would now get `bytes_unknown`. It now uses a 200 with `content-length: 0`.

**3. [Rule 1 - Test] Email guard regex**
- The plan's regex `[\w.+-]+@[\w-]+\.[a-z]{2,}` also matches `x@2x.png`. The guard drops matches that end in an image extension, so retina names stay allowed as the plan says. A test pins both sides.

**4. [Style]** `ruff format` on tests/test_hf_fixtures.py, committed in 40f635b. No logic change.
