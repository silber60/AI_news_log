## Summary

HF already returns the star count. `paper.githubStars` is in the `daily_papers` list payload next to `githubRepo`. On live W44, 145 of the 214 papers have a repo, and all 145 also have an int `githubStars`. The code already reads and validates the field: it is in `fetch._PAPER_KEYS` and `HfPaper.githubStars`. Selection therefore needs **no GitHub API call and no token**. HF lags GitHub by a few stars (0, 5 and 7 behind on the three repos checked), which is fine for a weekly ranking.

On live W44, 17 papers have at least 100 stars, so N = 10. Only 1 of these 10 (Hy-Nomas) was in the old upvote Top 10. Each paper is ranked by the star count of its linked repo, so a small paper attached to a large repo can win: rank 1 is `InternLM/xtuner` with 5,222 stars. The owner's rule (D-02) decides this; it is listed here as a pitfall only.

Per-article images are the weak spot. HF `mediaUrls` in the new Top 10 are almost all `.mp4`, and only one is an image (a 3.99 MB GIF). README images often sit behind redirects: `github.com/user-attachments/assets/...` returns a 302 to an S3 URL signed with `X-Amz-Expires=300`, and `huggingface.co/.../resolve/...` also redirects. Other README images are logos, SVG or WebP, or 2-8 MB files. With the recommended policy (no redirects, PNG/JPEG/GIF, at least 576 px wide, ratio 1.2-4.0, at most 1 MB, logo names skipped), coverage on the simulated Top 10 is **4/10**.

Two budget problems drive the plan. First, the current worst-case email is **87,105 B** against a 92,160 B cap. A separate 활용 아이디어 row costs +3,980 B, which leaves only about 1 KB. Putting the idea inside the existing 3-line cell costs +1,670 B. Second, `prompts/humanizer_ko.md:24` currently *tells* Claude to write 하다체 ("~한다"), which explains why 39 of the 40 preview fields fail the 해요체 check.

**Primary recommendation:** Rank by HF `githubStars` with a pure function. Fetch the README only from `raw.githubusercontent.com/{o}/{r}/HEAD/README.md` and accept images only from non-redirecting hosts (`cdn-uploads.huggingface.co`, `raw.githubusercontent.com`). Bump to Issue v3 with `github_stars` and `use_idea_ko`. Add a positive "ends in 요" check, and render the idea inside the summary-lines cell.

## 2. Selection (D-03/D-04)

```python
# newsletter/stages/select.py
STAR_MIN, N_MIN, N_MAX = 100, 3, 10

def has_repo(e: HfEntry) -> bool:
    r = e.paper.githubRepo
    return isinstance(r, str) and r.startswith("https://")   # same test as analyze._is_https

def stars(e: HfEntry) -> int | None:
    s = e.paper.githubStars
    return s if isinstance(s, int) and not isinstance(s, bool) and s >= 0 else None

def star_key(e: HfEntry) -> tuple:
    s = stars(e)
    return (-(s if s is not None else -1),   # missing stars sort after 0
            -e.paper.upvotes, -e.numComments,
            e.paper.submittedOnDailyAt, e.paper.id)  # existing deterministic tail

def select_top(entries: list[HfEntry]) -> list[HfEntry]:
    repos = sorted((e for e in entries if has_repo(e)), key=star_key)
    n_star = sum(1 for e in repos if (stars(e) or 0) >= STAR_MIN)
    n = min(max(n_star, N_MIN), N_MAX)
    picked = repos[:n]
    if len(picked) < n:                         # < 3 repos in the week
        others = sorted((e for e in entries if not has_repo(e)), key=sort_key)  # upvote key
        picked += others[: n - len(picked)]
    return picked
```

## 3. README image (D-08/D-09)

**README fetch:** `GET https://raw.githubusercontent.com/{o}/{r}/HEAD/README.md` with no API quota and no token. All 10 returned 200 (5-26 KB) [VERIFIED: live]. Details:
- Parse `{o}/{r}` from `githubRepo` with `^https://github\.com/([A-Za-z0-9-]{1,39})/([\w.-]{1,100}?)(?:\.git)?/?$`, and reject names containing `..`. This follows the T-01.1-08 allowlist style.
- Stream at most 256 KB. A 404 means no README image, with no `readme.md` or `.rst` retry. HEAD-ref raw URLs serve directly with no redirect [VERIFIED: httpx history empty].

**Parsing (regex, no new dependency):**
1. Drop `<!-- -->` comments and fenced code blocks.
2. Take `![alt](src "title")` and `<img ... src=...>` in document order, then `html.unescape` the src.
3. Resolve the URL:
   - `//x` becomes `https://x`.
   - `http://` is rejected.
   - A relative or `/`-rooted path becomes `https://raw.githubusercontent.com/{o}/{r}/HEAD/` + the path with `./` and `/` stripped. Reject any path containing `..`.
   - `https://github.com/{o}/{r}/(blob|raw)/{ref}/{path}` becomes `https://raw.githubusercontent.com/{o}/{r}/{ref}/{path}`.
4. Reject:
   - any query string or fragment (Gmail proxy issue, Phase 1.1 A2);
   - `.svg`, `.webp`, `.mp4` or `.mov`;
   - badge hosts and paths: `shields.io|badge|/actions/workflows/|pepy.tech|codecov|badgen|star-history|komarev`;
   - logo-like filenames: `logo|wordmark|lockup|emblem|icon|avatar`.
5. **Host allowlist for the stored URL:** `https://cdn-uploads.huggingface.co/` and `https://raw.githubusercontent.com/` only.
6. Probe at most 6 candidates per item with the existing `_read_head`, extended:
   - Use `follow_redirects=False`; a 3xx means `reason=redirect`. This is already the httpx default, and the enrich client sets nothing.
   - Read the total from `content-range: bytes 0-65535/<total>`. Both hosts send it [VERIFIED: live headers].
   - The rest is unchanged: Pillow header parse, then the width and ratio checks.

**Candidate order:** HF `mediaUrls` images first, then README candidates. The first candidate that passes every filter wins. An HF image that fails the cap falls through to the README, and the README is fetched only when needed.

**Prompt rules to add (analyze_paper.md, new `## 말투` section):**
- 모든 문장은 친근한 해요체로 끝냅니다: "~해요", "~이에요/예요", "~했어요", "~할 수 있어요". "~다."로 끝나는 하다체("제안했다", "모델이다")와 반말("~해", "~야")은 쓰지 않습니다. 명사로 끝내지도 않습니다("29.5% 증가.").

```python
_SENT_SPLIT = re.compile(r"(?<=[.!?])\s+(?=\S)")
_TAIL = re.compile(r"[\s\"'”’)\]」』]+$")
_HAEYO = re.compile(r"요[.!?~]*$")
HAEYO_FIELDS = ("summary_ko", "does_ko", "new_ko", "result_ko", "use_idea_ko")

def not_haeyo(text: str) -> bool:
    for s in _SENT_SPLIT.split(text.strip()):
        s = _TAIL.sub("", s)
        if s and not s.endswith("…") and not _HAEYO.search(s):
            return True
    return False
# in check(): errs.append(("tone", f"{field}가 해요체(~요)로 끝나지 않음")) per field
```

- **Positive check:** require every sentence to end in 요. A positive check beats a 하다체 blacklist, because it also catches noun endings ("증가.") and cannot false-match terms, since it only looks at the sentence end. Decimals like `99.3%` do not split, because the split needs whitespace after the dot.

## Common Pitfalls

1. **respx strict mocking breaks every e2e test.** The new raw.githubusercontent.com calls are unmocked, and respx raises an assertion, not an `httpx.HTTPError`, so `_NON_FATAL` does not catch it. Fix: add `mock_github(router, readmes=None)` to conftest, default 404, and call it inside `mock_hf_week` (as 01.1-03 did for `mock_enrich`).
2. **The enrich fixture covers the old Top 10.** `hf_papers_w44.json` has only the upvote Top 10 ids (`2610.37381, 2610.35684, 2610.32749, ...`). Under star selection, all 10 new ids return 404, so `enrich=partial`. Capture `/api/papers` and the models for the 10 star ids (about 20 HF calls). Build small synthetic README fixtures from the extracted `<img>` lines only, not full READMEs.
3. **Expected-order tests.** `test_e2e.py:43` and `test_select.py` compute expectations with the upvote `sort_key`. Switch them to the new rule. Fixture Top 10 differs from live at ranks 6 and 7: RSIHub 310 vs VibeGame 306 in the fixture.
4. **The humanizer prompt contradicts D-11** (line 24). Editing only analyze_paper.md leaves two conflicting instructions in one system prompt.
5. **The `default_analysis` fake is in 하다체.** With the tone check on, every e2e test would retry, and call-count assertions would break.
6. **Redirecting image hosts** (user-attachments, HF resolve). They pass a `follow_redirects=True` probe but may break in Gmail, and the signed target expires in 300 s. Probe with redirects off.
7. **Star ranking favors big umbrella repos** (xtuner 5,222 for one RL paper). D-02 locks the rule. Do not "fix" it silently.
