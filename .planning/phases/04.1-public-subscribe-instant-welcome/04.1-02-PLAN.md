## Phase Goal

**As a** reader who finds the site, **I want to** sign up with my name and email and get the latest issue right away, **so that** I can start reading this week instead of waiting for Monday, and every later Monday mail reaches me without the owner doing anything.

Extend the Phase 4 Apps Script into the one combined backend: subscribe, the live member list, the one-time import, and a welcome queue drained by a 1-minute trigger, plus the manifest and the Korean setup guide. Phase 4 unsubscribe behavior and the token vector stay unchanged.

Purpose: SUBS-01 (submissions land on the list with no owner action), SUBS-03 (the welcome mail) and SUBS-04 (the list the weekly send reads) all live in this one script.
Output: Code.gs, appsscript.json, README.md, tests/test_apps_script.py. The owner deploys it in 04.1-05.
</objective>

## Interface contracts (other plans depend on these exact names)

- Reply to action=subscribe with fmt=json: {"ok": true|false, "code": "ok"|"invalid"|"consent"|"busy"}. There is no per-address or per-issue code (research's ok_first is dropped to close the oracle; with no published issue the reply is plain ok). Form fields: name, email, consent (value yes), cv (consent version), website (honeypot), action=subscribe, fmt=json|html. 04.1-04 uses the same field names and these Korean messages: ok 신청됐어요. 매주 월요일 아침에 메일을 보내드려요. / invalid 이메일 주소를 다시 확인해 주세요. / consent 개인정보 수집에 동의해야 신청할 수 있어요. / busy 잠시 후 다시 신청해 주세요.
- action=members, body key=<SEND_LIST_KEY>: {"version": 1, "subscribers": [{"email": str, "name": str}]}; a wrong key: {"error": "forbidden"}. 04.1-03 reads this.
- action=import, body key=<ADMIN_KEY> and rows=<JSON array of {email, name}, at most 25>: {"version": 1, "added": n, "existing": n, "unsubscribed": n, "skipped": n}; over 25 rows: {"error": "too_many"}; bad rows: {"error": "bad_rows"}; a wrong key: {"error": "forbidden"}. 04.1-03 posts this.
- latest.json: the contract in 04.1-01-PLAN.md (keys endpoint, from_name, html, issue_id, slots, subject, text, unsubscribe_page, version).
- Script property ↔ GitHub secret: TOKEN_SECRET ↔ UNSUBSCRIBE_TOKEN_SECRET, LIST_KEY ↔ UNSUBSCRIBE_LIST_KEY, SEND_LIST_KEY ↔ SUBSCRIBER_LIST_KEY, ADMIN_KEY ↔ SUBSCRIBE_ADMIN_KEY. CONSENT_VERSIONS = ['2026-11-04']. Runtime properties (no PII): q_<id> (queued welcome, value = attempt count), w_<id> (time queued, 24 h), wd_<yyyyMMdd> (queued today).
