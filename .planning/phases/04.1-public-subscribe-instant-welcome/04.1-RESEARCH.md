### Locked Decisions

#### Subscribe flow
- **D-01 (owner):** Single opt-in. A form submit registers the reader at once and sends the welcome mail. There is no confirmation-mail step. This means someone can submit another person's address. Claude's default mitigations:
  - a honeypot field
  - an email-format check
  - one row per address: a re-submit never creates a duplicate row, and an address gets at most one welcome mail per 24 h
  - a per-address rate limit
  - the welcome mail carries the personal 구독 해지 link plus one line: "직접 신청하지 않으셨다면 아래 구독 해지를 눌러 주세요."
  — **Reversibility:** reversible. Adding a confirm step later only changes the flow for new sign-ups.
- **D-02:** The form posts to the same Apps Script web app as unsubscribe (Phase 4 D-10). The page shows a success or error message in place. Every address and name stays out of the URL, the repo, Actions logs and artifacts.

#### Welcome mail (SUBS-03)
- **D-03 (owner):** The welcome mail is a welcome line plus the latest issue.
  - It opens with a short welcome line, e.g. "구독해 주셔서 고마워요. 매주 월요일 오전 8시에 보내드려요."

  - The subject is `[환영] <headline_ko>`.
  - It carries the personal 구독 해지 link and the List-Unsubscribe headers, the same as the weekly mail.
- **D-04:** It must arrive within minutes and with no owner action. Research picks the mechanism under these constraints:

  - The Sheet stores the consent time and a consent-text version.
  - On unsubscribe, the name and email are deleted from the Sheet. Only the token id stays in the `unsubscribes` tab, so the weekly send still skips that address.

#### Existing subscribers and re-subscribe
- **D-06 (owner):** An automated one-time import.

- **D-07 (owner):** Re-subscribe is allowed. An address that unsubscribed can submit the form again. It becomes active again, its token id is cleared from the unsubscribe list, and it gets the welcome mail.

#### Weekly send (SUBS-04)
- **D-08:** The weekly `mode=send` reads the live list from Apps Script.

## Summary

The repo is ready on the Python side and only half-ready on the Google side. At HEAD, `UNSUBSCRIBE_ENDPOINT = None` (`newsletter/delivery/unsubscribe.py:28`). STATE.md line 13 says "04-04 Task 3 Google setup pending". `data/issues/` does not exist yet, so no issue is published (`ls` this session). The owner's 4.1 setup is therefore the first deployment of the web app. The script's first deploy is the one allowed **새 배포**. Every later change is **배포 관리 → 수정 → 새 버전**. The code must also handle "no issue published yet", because that is today's state.

The welcome mail cannot use `GmailApp`/`MailApp` as-is. Their options are `attachments, bcc, cc, from, htmlBody, inlineImages, name, noReply, replyTo` with no custom headers [CITED: developers.google.com/apps-script/reference/gmail/gmail-app], so D-03's List-Unsubscribe headers would be lost. The fix is the **Gmail advanced service**. Apps Script builds a raw RFC 2822 multipart message, with the same headers `send.build_message` writes, and calls `Gmail.Users.Messages.send({raw}, 'me')`. `raw` is "an RFC 2822 MIME message encoded as base64URL" [CITED: developers.google.com/workspace/gmail/api/guides/sending]. The HTML comes from render.py: the publish job (and `site`) writes `docs/welcome/latest.json`, which holds the email-variant HTML and text of the newest published issue rendered with a welcome flag and two placeholders, plus the `[환영]` subject. Apps Script fetches it with `UrlFetchApp`, fills the HTML-escaped greeting and the personal unsubscribe link, and sends.

The form uses `fetch()` POST with a `URLSearchParams` body. The browser sends that as `application/x-www-form-urlencoded`, a CORS-safelisted type, so there is no preflight. Apps Script cannot answer `OPTIONS` [community-sourced, MEDIUM]. The redirect is followed, and the JSON reply comes from `ContentService`. If the browser blocks the read (a mobile Chrome CORS failure is reported in the community), the page shows a neutral "확인하지 못했어요" message. Re-submitting is idempotent, so a retry is safe. Without JS, the form still works as a plain POST with `fmt=html` and lands on an Apps Script result page. JSONP and `no-cors` are rejected: JSONP is a GET, so the address would go in the URL, and Google warns JSONP must be read-only [CITED: developers.google.com/apps-script/guides/content]. `no-cors` cannot tell success from error.

**Primary recommendation:** Extend Code.gs with `action=subscribe | members | import` routes and a Gmail-advanced-service welcome sender, keeping the Phase 4 routes byte-compatible. Publish `docs/welcome/latest.json` from `web.build_site()` using `render_html/render_text(..., welcome=True)`. Gate the forms, the email `구독하기` link and the live-list send on the one constant `UNSUBSCRIBE_ENDPOINT`. Cut over in one owner-gated commit, then run the import job right away. Remove the CSV path in a final cleanup plan.

### Pattern 2: Welcome payload `docs/welcome/latest.json`
`web.build_site()` runs on every publish and every `site` run [VERIFIED: newsletter/web.py:104-122; __main__.py `_publish` calls `_build_site`], so latest is always `load_issues()[0]`, the newest `issue_id` (`web.py:60` sorts `reverse=True`). ```python
# render.py (sketch; names are proposals)
GREETING_SLOT = "__MODAK_GREETING__"        # [A-Z_] only: survives Jinja autoescape and css_inline
UNSUB_SLOT = "__MODAK_UNSUB_URL__"
WELCOME_MAX_BYTES = MAX_EMAIL_BYTES - 1024  # fill growth: name <= 40 chars escaped, link ~86 B

def build_subject(issue, mode: Literal["preview", "test", "send", "welcome"]) -> str:
    subject = issue.headline_ko
    if mode == "test":
        subject = "[TEST] " + subject
    elif mode == "welcome":
        subject = "[환영] " + subject           # D-03
    return subject.replace("\r", " ").replace("\n", " ")

def render_welcome(issue: Issue) -> dict:
    html = render_html(issue, GREETING_SLOT, unsubscribe_url=UNSUB_SLOT, welcome=True)
    if len(html.encode("utf-8")) >= WELCOME_MAX_BYTES:
        raise RenderTooLarge(f"bytes={len(html.encode('utf-8'))}")
    return {"subject": build_subject(issue, "welcome"), "html": html,
            "text": render_text(issue, GREETING_SLOT, unsubscribe_url=UNSUB_SLOT, welcome=True)}

### Pattern 3: Code.gs routing that keeps Phase 4 intact
Today `doPost` handles `action === 'list'` first and treats everything else as a token (`Code.gs:35-42`) [VERIFIED]. Insert the new actions before the token branch and leave the list and token branches untouched:

```javascript
function doPost(e) {
  const p = params_(e);
  if (p.action === 'list') return list_(String(p.key || ''));          // unchanged
  if (p.action === 'members') return members_(String(p.key || ''));
  if (p.action === 'import') return import_(String(p.key || ''), String(p.rows || ''));
  if (p.action === 'subscribe') return subscribe_(p);
  const t = String(p.t || '').toLowerCase();                           // unchanged below
  if (!TOKEN_RE.test(t)) return done_('링크가 올바르지 않아요.');
  record_(t, p['List-Unsubscribe'] === 'One-Click' ? 'one-click' : 'button');
  return done_('구독이 해지됐어요. 다음 주부터는 메일이 가지 않아요.');
}
```
`params_` already merges a form-urlencoded body when `e.parameter` lacks `action` (`Code.gs:46-60`) [VERIFIED]. That covers the subscribe body whether or not Apps Script merges it itself.

`record_` (the D-05 extension): in the same lock, after the existing append-if-absent, find `t` in `subscribers!A:A` with `createTextFinder(t).matchEntireCell(true)` and `deleteRow`. The unsubscribe sheet write stays byte-identical in effect.

### Pattern 4: Sheet schema (Claude's discretion; recommended)
- `unsubscribes`: unchanged `id | at | via` (Phase 4, `Code.gs:129`).
- `subscribers`: `id | email | name | status | consent_at | consent_version | source | created_at | welcomed_at`
  - `id` = `tokenFor_(email, TOKEN_SECRET)`, stored as text (`setNumberFormat('@')` on A:A, as Phase 4 does)
  - `email` normalized `trim().toLowerCase()`, ≤ 254 chars
  - `name` trimmed, control characters removed, ≤ 40 chars, leading `= + - @` stripped (formula injection)
  - `status` ∈ `active` (single opt-in). The column leaves room for a future `pending` with double opt-in; `members_` returns only `active`.
  - `consent_at`: ISO time; `consent_version`: e.g. `2026-11-04` from an allow-list in Code.gs, mirrored by a Python constant (`newsletter/web.py CONSENT_VERSION`) and checked by a static test
  - `source` ∈ `form | import`; import rows get `consent_version = import`
  - `welcomed_at`: ISO time or empty
- Script properties hold no PII: `SHEET_ID, TOKEN_SECRET, LIST_KEY, SEND_LIST_KEY, ADMIN_KEY`, plus runtime counters `w_<id>` (last welcome, pruned after 24 h) and `wd_<yyyyMMdd KST>` (welcomes today, pruned after 2 days).

Key names: `SEND_LIST_KEY` ↔ GitHub secret `SUBSCRIBER_LIST_KEY`; `ADMIN_KEY` ↔ `SUBSCRIBE_ADMIN_KEY`. Keep three separate keys. `LIST_KEY` leaks pseudonymous ids only. `SEND_LIST_KEY` leaks every name and address, so it is send-gated. `ADMIN_KEY` writes rows and lives only in the import workflow. Unlike `TOKEN_SECRET`, all three can be rotated: change the property and the secret together. The new secret names avoid the `UNSUBSCRIBE_` prefix, so `test_unsubscribe_secrets_only_in_deliver`'s `text.count("UNSUBSCRIBE_") == 2 + 2` stays true [VERIFIED: tests/test_workflow_static.py:146].

### Pattern 5: `subscribe_` decision table
| Case | Row | `unsubscribes` | Welcome | Reply code |
|------|-----|----------------|---------|------------|
| honeypot `website` non-empty | none | — | no | `ok` (silent) |
| bad email / no consent / unknown consent version | none | — | no | `invalid` / `consent` |
| rate-limited (`CacheService` `rl:<id>` > 3 per 6 h, or `rl:all` > 30/h) | none | — | no | `busy` |
| new address | append `active` | — | yes, if `w_<id>` is absent or older than 24 h and under the daily cap | `ok` |
| previously unsubscribed (D-07) | append `active` | delete the id row | same rule | `ok` |
| already active | update name only if empty; never duplicate | — | **no** | `ok` (the same as new) |
| no published issue (`issue_id: null`) | as above | as above | no; `welcomed_at` stays empty | `ok_first` (copy: 첫 메일은 월요일에) |

Return the same `ok` for new and already-active, so the endpoint is not an "is X subscribed?" oracle. Hold `LockService.getScriptLock().waitLock(10000)` only around the Sheet and Properties read-modify-write. Send the mail after releasing it; Gmail takes about 1-2 s. A lock timeout throws, so catch it and reply `busy`. If the send fails, clear `welcomed_at` and `w_<id>` and still reply `ok`. The weekly send will reach the reader, and no address goes in the error text.

CacheService is the right tool for short windows only. Its max TTL is 21,600 s (6 h), and entries "may be evicted early" [CITED: developers.google.com/apps-script/reference/cache/cache]. The 24 h welcome dedupe therefore lives in PropertiesService (9 KB/value, 500 KB/store, 50,000 reads+writes/day [CITED: developers.google.com/apps-script/guides/services/quotas]). Only pseudonymous ids are stored, and old entries are pruned on each write.

### Pattern 6: Welcome MIME through the Gmail advanced service
```javascript
// Sketch. Header values mirror newsletter/delivery/send.py build_message.
function sendWelcome_(email, name, t) {
  const r = UrlFetchApp.fetch(LATEST_URL, { muteHttpExceptions: true, followRedirects: true });
  if (r.getResponseCode() !== 200) return 'fetch';
  const d = JSON.parse(r.getContentText('UTF-8'));
  if (d.version !== 1 || !d.issue_id) return 'no_issue';
  const g = greetingFor_(name);                       // port of subscribers.display_name
  const link = d.unsubscribe_page + t;
  const html = fill_(d.html, d.slots, escapeHtml_(g), link);   // returns null unless each slot occurs once
  const text = fill_(d.text, d.slots, g, link);
  if (!html || !text || Utilities.newBlob(html).getBytes().length >= 92160) return 'shape';
  const me = Session.getEffectiveUser().getEmail();
  const b = 'b' + Utilities.getUuid().replace(/-/g, '');
  const mime = [
    'From: ' + word_('모닥로그 AI 리포트') + ' <' + me + '>',
    'To: ' + email,                                     // address only; the name never goes in a header
    'Subject: ' + word_(String(d.subject).replace(/[\r\n]/g, ' ')),
    'MIME-Version: 1.0',
    'List-Unsubscribe: <mailto:' + me + '?subject=unsubscribe>, <' + d.endpoint + '?t=' + t + '>',
    'List-Unsubscribe-Post: List-Unsubscribe=One-Click',
    'Content-Type: multipart/alternative; boundary="' + b + '"', '',
    '--' + b, 'Content-Type: text/plain; charset=UTF-8', 'Content-Transfer-Encoding: base64', '', b64_(text),
    '--' + b, 'Content-Type: text/html; charset=UTF-8', 'Content-Transfer-Encoding: base64', '', b64_(html),
    '--' + b + '--', ''
  ].join('\r\n');
  Gmail.Users.Messages.send({ raw: Utilities.base64EncodeWebSafe(mime, Utilities.Charset.UTF_8) }, 'me');
  return 'sent';
}
function b64_(s) { return Utilities.base64Encode(s, Utilities.Charset.UTF_8).replace(/(.{76})/g, '$1\r\n'); }
function word_(s) { /* RFC 2047 B-words, chunked by ~12 code points so no word passes 75 chars */ }
```
`Utilities.base64Encode(String,Charset)`, `base64EncodeWebSafe(String,Charset)`, `computeHmacSha256Signature(String,String,Charset)` and `getUuid()` exist [CITED: developers.google.com/apps-script/reference/utilities/utilities]. Use `split(slot).join(value)`, not `String.replace`, because `$&` in a name would be interpreted by `replace`. Wrap base64 at 76 characters: an unwrapped 120 KB line passes RFC 5322's 998-character limit.

`greetingFor_` must match `display_name` (`subscribers.py:86-90`): remove non-printable characters, trim, drop a trailing `님`, trim again, return `<n>님` or `구독자님`. Python's `str.isprintable()` rejects categories C* and Z* except the ASCII space. The JS port is `/[\p{C}\p{Zl}\p{Zp}]|[^\S ]/gu`-style removal. Pin it with shared vectors in both test suites and selfTest: `' 홍길동님 '`→`홍길동님`, `''`→`구독자님`, `'<b>'`→`<b>님` (escaped to `&lt;b&gt;님` only in HTML).

### Anti-Patterns to Avoid
- **Address or name in a URL query** (JSONP, `GET ?email=`, `form.action += "?email="`). D-02. The token query `?t=` stays allowed (Phase 4).
- **Returning HtmlService for `fmt=json`.** HtmlService output is not readable cross-origin. Return `ContentService.createTextOutput(JSON.stringify(...)).setMimeType(ContentService.MimeType.JSON)`.
- **`GmailApp`/`MailApp` for the welcome.** It drops the List-Unsubscribe headers.
- **A new deployment.** It creates a new URL [CITED: developers.google.com/apps-script/concepts/deployments via 04-RESEARCH].
- **Logging in Code.gs.** Keep the Phase 4 rule: one `Logger.log` (selfTest) and no `console.` (tested in `tests/test_unsubscribe.py`).
- **Telling the browser "이미 구독 중이에요".** That is an enumeration oracle.
- **Writing the live list to `archive/`, `status.json` or `$GITHUB_STEP_SUMMARY`.**

## Common Pitfalls

### Pitfall 1: The welcome mail loses List-Unsubscribe silently
**What goes wrong:** An implementer uses `GmailApp.sendEmail` because it is simpler, and the headers vanish. **Avoid:** a static test asserts `Gmail.Users.Messages.send` appears in Code.gs and `GmailApp.sendEmail`/`MailApp.sendEmail` do not. The owner checks "원본 보기" on the real sign-up mail.

### Pitfall 2: The Gmail advanced service is not enabled, or the scopes are not granted
**What goes wrong:** `ReferenceError: Gmail is not defined`, or an authorization error on the first sign-up. **Avoid:** ship `apps_script/appsscript.json` with `dependencies.enabledAdvancedServices: [{"userSymbol":"Gmail","serviceId":"gmail","version":"v1"}]` [CITED: developers.google.com/apps-script/manifest/dependencies field names], `"runtimeVersion": "V8"`, `"timeZone": "Asia/Seoul"`, and `"webapp": {"executeAs": "USER_DEPLOYING", "access": "ANYONE_ANONYMOUS"}` [CITED: developers.google.com/apps-script/manifest/web-app-api-executable allowed values]. selfTest calls a cheap Gmail API method, so the owner authorizes every scope before deploying. Consider explicit `oauthScopes` (`gmail.send`, `spreadsheets`, `script.external_request`, `userinfo.email`). The exact scope set is [ASSUMED]; selfTest proves it.

### Pitfall 3: The "Google hasn't verified this app" screen stops the owner
It is the owner's own consumer project, so the owner clicks 고급 → (안전하지 않음) 이동 [ASSUMED]. Put this in the Korean steps.

### Pitfall 4: A stale latest.json after a send
Pages serves `cache-control: max-age=600` [VERIFIED: curl -sI https://silber60.github.io/AI_news_log/ this session]. A query-string cache-buster is unreliable: a `?v=1` request returned `x-cache: HIT` right after a MISS on the bare URL [VERIFIED: curl this session; one sample, so treat the cache-key behavior as unknown]. **Accept it:** for up to about 10 minutes after the Monday send, a new reader may get the previous issue, then also gets the new one on Monday. Do not try to fix it.

### Pitfall 5: A placeholder mangled by escaping or inlining
**Avoid:** use only `[A-Z_]` in slots. Test that `render_welcome` output contains each slot exactly once in HTML and in text. Apps Script refuses to send unless the counts are 1.

### Pitfall 6: Size after the fill
The worst case today is 78,390 B (04-07 SUMMARY). The welcome row adds a few hundred bytes. Python gates at `MAX_EMAIL_BYTES - 1024`; Apps Script re-checks `< 92160` after the fill.

### Pitfall 7: Formula injection in the Sheet
A name like `=IMPORTXML(...)` written by `appendRow` can be evaluated [ASSUMED]. **Avoid:** strip leading `= + - @` from names, reject emails starting with them, and set all `subscribers` columns to plain text (`'@'`) in `setup()`.

### Pitfall 8: Mail-bomb abuse through single opt-in
**Avoid:** honeypot; the per-id CacheService limit; "already active ⇒ no mail"; the 24 h `w_<id>`; a global daily cap `wd_<date>` (recommend 50). Apps Script's consumer quota is 100 email recipients/day [CITED: quotas page]. Whether Gmail API sends count against it is [ASSUMED no]. Gmail's own limit is "more than 500 emails sent in a day" [CITED: support.google.com/mail/answer/22839], and the weekly SMTP send shares it. When the cap is hit, the reader is still registered and the Monday mail covers them.

### Pitfall 9: The CORS read fails on some browsers
A community report says text/plain fetch failed on mobile Chrome [community, LOW]. The server may already have processed the request. **Avoid:** `MSG.unknown` = "신청 결과를 확인하지 못했어요. 몇 분 뒤에도 메일이 없으면 한 번 더 신청해 주세요." A re-submit is safe because of the dedupe. The owner tests from a phone in the checkpoint.

### Pitfall 10: Cut-over ordering
If `UNSUBSCRIBE_ENDPOINT` is set (live list on) and a `mode=send` runs before the import, the send reaches only form sign-ups. **Avoid:** a zero-length live list raises `NoSubscribersError` (keep the `parse_subscribers` semantics), so it fails closed. The owner runs the import job right after the cut-over commit, before any send. Phase 5 has no cron yet, so no send can fire in between.

### Pitfall 11: Sheet version history keeps deleted PII
Deleting a row does not erase Google Sheets revision history [ASSUMED]. Mention 구독 해지 시 지체 없이 삭제 on the privacy page without promising erasure from backups. The owner can delete old versions by hand if asked.

### Pitfall 12: Nav `#subscribe` on sub-pages
`_base.html.j2:57` hard-codes `href="#subscribe"`. `/unsubscribe/` passes `subscribe_url=None` (`web.py:96`) [VERIFIED]. The new `/privacy/` page must also pass `subscribe_url=None`, or pass `../#subscribe` with a new context var.

### Pitfall 13: Humanizer lint on fixed copy
The lint flags a `closer` when a text has ≥ 3 sentences and its last sentence is ≤ 18 chars with no digit (`humanize.py:107`, `CLOSER_MAX = 18`) [VERIFIED]. It also flags non-해요 endings and emoji in sentences. Lint every new sentence individually (welcome line, D-01 line, form messages, consent, privacy paragraphs), the way `test_code_gs_korean_passes_humanizer` does.

### Python: fail-closed member list (mirrors `fetch_unsubscribed`)
```python
# newsletter/delivery/members.py (sketch)
def fetch_subscribers(endpoint: str, key: str, client: httpx.Client | None = None) -> tuple[list[Subscriber], int]:
    """Active rows from the Sheet. Key in the POST body only; any doubt raises DeliveryError."""
    own = client is None
    c = client or httpx.Client(timeout=LIST_TIMEOUT)
    try:
        try:
            r = c.post(endpoint, data={"action": "members", "key": key}, follow_redirects=True)
        except httpx.HTTPError as e:
            raise DeliveryError(f"subscriber list {type(e).__name__}") from None
        if r.status_code != 200:
            raise DeliveryError(f"subscriber list status={r.status_code}")
        try:
            data = r.json()
            rows = data["subscribers"]
            if data.get("version") != 1 or not isinstance(rows, list):
                raise TypeError
        except (ValueError, KeyError, TypeError):
            raise DeliveryError("subscriber list unreadable") from None
    finally:
        if own:
            c.close()
    out, seen, skipped = [], set(), 0
    for row in rows:
        email = str(row.get("email", "")).strip() if isinstance(row, dict) else ""
        if not _valid_email(email) or email.lower() in seen:
            skipped += 1
            continue
        seen.add(email.lower())
        out.append(Subscriber(email=email, name=str(row.get("name") or "").strip()))
    if not out:
        raise NoSubscribersError(f"no valid subscribers (skipped={skipped})")
    return out, skipped
```
Note: `unsubscribe.py:58` uses `except ValueError, KeyError, TypeError:`, the Python 3.14 PEP 758 form without parentheses. Either form is fine under `target-version = "py314"` (pyproject.toml:29). Follow the file's existing style.
