# Phase 4.1: Public Subscribe & Instant Welcome Issue - Context

**Gathered:** 2026-11-04
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase turns on subscribing on the one GitHub Pages site from Phase 4. A reader fills the form (이름, 이메일, 동의). The address lands on the Google Sheet with no owner action. Within minutes the reader gets a welcome mail: a welcome line, then the latest published issue with their name in the greeting. From then on, the weekly send reads the live list from the Sheet instead of the `SUBSCRIBERS_CSV` secret (SUBS-01, SUBS-03, SUBS-04).

It also closes the open Phase 4 items. The owner does the Google setup once, with one combined Apps Script (subscribe + unsubscribe). That closes 04-04 Task 3 and the D-10/D-12 click-to-unsubscribe check. Phase 4's last step, the owner's first `mode=send` with live-page proof, stays as planned in 04-07 Task 3.

Out of scope: per-subscriber topics (SUBS-02, v2), cron, send ledger, run report (Phase 5).

</domain>

<decisions>
## Implementation Decisions

### Subscribe flow
- **D-01 (owner):** Single opt-in. A form submit registers the reader at once and sends the welcome mail. There is no confirmation-mail step. This means someone can submit another person's address. Claude's default mitigations:
  - a honeypot field
  - an email-format check
  - one row per address: a re-submit never creates a duplicate row, and an address gets at most one welcome mail per 24 h
  - a per-address rate limit
  - the welcome mail carries the personal 구독 해지 link plus one line: "직접 신청하지 않으셨다면 아래 구독 해지를 눌러 주세요."
  — **Reversibility:** reversible. Adding a confirm step later only changes the flow for new sign-ups.
- **D-02:** The form posts to the same Apps Script web app as unsubscribe (Phase 4 D-10). The page shows a success or error message in place. Every address and name stays out of the URL, the repo, Actions logs and artifacts.

### Welcome mail (SUBS-03)
- **D-03 (owner):** The welcome mail is a welcome line plus the latest issue.
  - It opens with a short welcome line, e.g. "구독해 주셔서 고마워요. 매주 월요일 오전 8시에 보내드려요."
  - The latest published issue follows, unchanged, with the reader's name in the greeting.
  - The subject is `[환영] <headline_ko>`.
  - It carries the personal 구독 해지 link and the List-Unsubscribe headers, the same as the weekly mail.
- **D-04:** It must arrive within minutes and with no owner action. Research picks the mechanism under these constraints:
  - Preferred: Apps Script sends through the owner's Gmail (ROADMAP direction), filling an email-ready latest-issue HTML that the publish job puts on Pages with greeting and unsubscribe placeholders.
  - Rejected: anything that puts an address in a GitHub workflow payload, log or artifact (Actions logs are public).
  - The email stays under 92,160 B, and the HTML must match what the weekly mail renders (one source of truth: render.py).

### Privacy and consent
- **D-05 (owner):** A required consent checkbox and a `/privacy/` page (개인정보 처리방침) linked from the site footer and the form.
  - Consent text names the items collected (이름, 이메일), the purpose (뉴스레터 발송) and how long they are kept (구독 해지 때까지).
  - The Sheet stores the consent time and a consent-text version.
  - On unsubscribe, the name and email are deleted from the Sheet. Only the token id stays in the `unsubscribes` tab, so the weekly send still skips that address.

### Existing subscribers and re-subscribe
- **D-06 (owner):** An automated one-time import.
  - A `workflow_dispatch` job (e.g. `import-subscribers`) reads the `SUBSCRIBERS_CSV` secret and posts each row to Apps Script with an admin key, marked as already subscribed.
  - It sends no welcome mail and logs counts only.
  - Afterwards the owner deletes the `SUBSCRIBERS_CSV` secret by hand, and the code stops reading it.
- **D-07 (owner):** Re-subscribe is allowed. An address that unsubscribed can submit the form again. It becomes active again, its token id is cleared from the unsubscribe list, and it gets the welcome mail.

### Weekly send (SUBS-04)
- **D-08:** The weekly `mode=send` reads the live list from Apps Script.
  - The list holds active name+email rows. It is fetched with a send-only key in the Deliver step only, over HTTPS, and never written to disk, artifacts or logs.
  - Rows are deduplicated by normalized address, and anything on the unsubscribe list is skipped (Phase 4 D-13 filter stays).
  - If the list cannot be read, the send stops (fail closed, the Phase 4 pattern).
  - Logs carry counts only.
- **D-09:** The subscribe page is linked from the email footer (ROADMAP SC1). That serves forwarded mail. It is a `구독하기` link to the site's form.

### Turning the forms on
- **D-10:** `SUBSCRIBE_URL` (Phase 4 D-09) is set once the owner deploys the combined script. That shows the hero form, the bottom CTA form and the nav `구독하기` button. The owner asked for subscribing to be on the 지난 호 page, and since the 지난 호 section is on the same home page, that is covered.
- **D-11:** The owner does the Google setup once, with the combined script.
  - The Phase 4 `apps_script/Code.gs` is extended rather than replaced: same deployment, same Sheet "모닥로그 AI 리포트 구독 관리".
  - Existing token and unsubscribe behavior must not change. The Phase 4 test vector stays valid.
  - Claude supplies the script and step-by-step Korean setup. The owner reports only the `/exec` URL and self-test results, never secret values.

### Claude's Discretion
- Sheet schema (tabs, columns), status values, and the admin and list key names
- Form UX messages, loading and error states, and the honeypot field name
- The privacy page wording beyond the D-05 items. It must pass the humanizer lint, and it is a generic notice, not legal advice.

</decisions>

## Existing Code Insights

### Reusable Assets
- `apps_script/Code.gs`: doGet/doPost routing, a token HMAC matching Python, a `LIST_KEY` list endpoint, setup and selfTest
- `newsletter/delivery/unsubscribe.py`: `token()`, `fetch_unsubscribed()` (fail closed, `follow_redirects=True`)
- `newsletter/delivery/deliver.py`: per-recipient render with greeting and unsubscribe link; `SUBSCRIBERS_CSV` parsing to replace
- `templates/web/home.html.j2`: the form markup, already built and hidden behind `SUBSCRIBE_URL = None`
- `newsletter/web.py` `build_site`: the place to add `/privacy/` and, if research picks it, the email-ready latest-issue HTML

### Established Patterns
- Secrets appear only in the Deliver step, and send-only keys are gated with `inputs.mode == 'send'`. The Build step has exactly one `secrets.`.
- Logs carry counts and codes only; `tests/test_redaction.py` and `tests/test_workflow_static.py` guard this.
- Owner checkpoints for anything in Google or GitHub settings.
