# 문체 규칙 (humanizer)

모든 필드의 문장은 사람이 쓴 뉴스레터처럼 읽혀야 합니다. 아래 규칙을 지킵니다. 사실은 그대로 두고, 사실을 부풀리는 꾸밈만 뺍니다. 규칙마다 "대신" 뒤에 고친 예를 붙였습니다.

## 과장하지 않기
- 과장 표현을 쓰지 않습니다: 혁신적, 획기적, 게임 체인저, 판도를 바꾸는, 패러다임 전환, 새로운 지평, 놀라운, 강력한, 압도적, 혁명적, 차원이 다른, 역대급. 형용사 대신 무엇을 얼마나 했는지 적고, 그런 수치가 입력에 없으면 수식어 없이 한 일만 적습니다. 예) "강력한 성능을 보여요" 대신 "수학 benchmark에서 기존 모델보다 4점 높았어요".
- 중요성이나 앞날을 덧붙이지 않습니다: "~의 중요성을 보여 줬어요", "새 기준을 세웠어요", "이정표가 될 거예요", "한 획을 그었어요", "앞으로가 기대돼요", "의미가 커요". 마지막 사실에서 끝냅니다. 예) "로봇 연구의 이정표가 될 모델이에요" 대신 "로봇 팔 조작 성공률을 12% 올렸어요".
- 광고 문구를 쓰지 않습니다: "주목할 만한", "눈여겨볼", "꼭 알아야 할". 예) "꼭 알아야 할 모델이에요" 대신 "코드와 가중치를 함께 공개했어요".
- AI가 유독 자주 쓰는 말을 몰아 쓰지 않습니다: 다양한, 효과적으로, 원활한, 극대화, 최적화된, 심층적, 면밀히, 핵심적인. 예) "다양한 작업에서 성능을 극대화해요" 대신 "번역과 요약에서 점수가 올랐어요".
- 단순한 동사를 긴 말로 돌리지 않습니다: "~의 역할을 해요", "~로 자리매김했어요", "~로서 기능해요". 예) "검색 엔진의 역할을 해요" 대신 "검색 엔진이에요".
- 사실 뒤에 해석을 덧붙이지 않습니다: "~를 보여 주며", "~를 시사해요", "~를 강조해요". 예) "정확도를 높이며 데이터의 중요성을 강조해요" 대신 "정확도를 높였어요".
- 관계를 흐리게 말하지 않습니다: "~와 관련된", "~와 연관된" 대신 무엇이 무엇을 하는지 적습니다. 입력이 관계를 말하지 않으면 흐린 말을 그대로 두고 지어내지 않습니다. 예) "음성과 관련된 모델이에요" 대신 "음성을 글로 바꾸는 모델이에요".

## 꾸민 대비를 쓰지 않기
- "단순히 ~가 아니라 ~예요", "~뿐만 아니라 ~까지", "~에 그치지 않고", "~를 넘어 ~로" 같은 대비 문형을 쓰지 않습니다. 아무도 주장하지 않은 쪽을 부정해서 다른 쪽을 커 보이게 만드는 문형입니다. 두 문장으로 나눈 "~는 아니에요. ~예요."도 같습니다. 하려는 말을 바로 씁니다. 예) "단순한 요약 모델이 아니라 추론까지 하는 모델이에요" 대신 "요약과 추론을 함께 하는 모델이에요".
- 대비는 앞쪽이 독자가 실제로 믿을 만한 생각을 바로잡을 때, 또는 양쪽 모두 정보일 때만 남깁니다. 예) "사람이 아니라 로봇이 직접 물체를 옮겨요"는 정보가 있으니 그대로 씁니다.
- 깊어 보이는 격언을 쓰지 않습니다: "본질적으로", "근본적으로", "결국 핵심은", "진정한 ~", "~의 언어", "~ 그 자체". 예) "본질적으로 진정한 범용 에이전트예요" 대신 "웹 검색과 코드 실행을 한 모델에서 해요".
- 아무도 하지 않은 반론에 답하지 않습니다: "오해하지 마세요", "~라고 생각할 수 있지만", "~하고 싶겠지만". 예) "작은 모델이라 약하다고 생각할 수 있지만 성능이 좋아요" 대신 "7B 모델로 70B 모델과 비슷한 점수를 냈어요".

## 리듬을 규칙으로 맞추지 않기
- 셋을 억지로 나열하지 않습니다. 실제로 항목이 셋일 때만 셋을 쓰고, 세 문장을 같은 꼴로 맞추지 않습니다. 예) "빠르고, 정확하고, 가벼워요" 대신 "같은 정확도에서 두 배 빨라요".
- 같은 말로 시작하는 문장을 이어 쓰지 않습니다("이 모델은 … 이 모델은 …"). "이 논문은", "본 연구는", "이 모델은" 같은 주어 반복을 줄이고 한 일을 바로 씁니다. 예) "이 모델은 글을 읽어요. 이 모델은 표도 읽어요" 대신 "글과 표를 함께 읽어요".
- 대시(— 또는 –)나 ` -- `로 문장을 잇지 않습니다. 쉼표, 마침표, 괄호, 콜론을 씁니다. 모델 이름, 코드, URL 안의 하이픈(GPT-5, Vision-Language-Action)은 그대로 둡니다. 예) "속도가 빨라요 — 비용도 낮아요" 대신 "속도가 빠르고 비용도 낮아요".
- 앞 문장을 되풀이하는 짧은 마무리 한 줄을 붙이지 않습니다: "이게 핵심이에요.", "기억해 둘 만해요.", "주목할 부분이에요." 마지막 사실에서 끝냅니다. 예) "검색 단계를 줄였어요. 이게 핵심이에요." 대신 "검색 단계를 세 번에서 한 번으로 줄였어요."
- 단서를 겹쳐 붙이지 않습니다: "~일 수도 있을 것 같아요", "어쩌면 아마도". 입력이 뒷받침하는 단서 하나만 남깁니다. 예) "어쩌면 더 빨라질 수도 있을 것 같아요" 대신 "더 빨라질 수 있어요".
- 이중 피동을 쓰지 않고 누가 하는지 드러냅니다: "되어지다", "보여지다", "만들어지게 되었어요". 예) "새 데이터셋으로 학습되어졌어요" 대신 "연구진이 새 데이터셋으로 학습했어요".
- 영어 하이픈 복합어 규칙은 한국어에 해당하지 않습니다. 영어 모델 이름과 용어의 하이픈은 원문대로 둡니다.

## 형식
- 굵은 글씨, 마크다운 기호, 제목 표시(#), 목록 기호(-), "라벨: 내용" 꼴의 목록, 따옴표 강조를 쓰지 않습니다. 출력은 평문입니다. 예) "성능: 높음, 속도: 빠름" 대신 "점수가 오르고 속도도 빨라졌어요".
- 이모지와 화살표(→)를 쓰지 않습니다. 헤드라인의 emoji 필드만 예외입니다. 예) "🚀 출시했어요" 대신 "출시했어요".
- 곧은 따옴표(" ')만 씁니다. 둥근 따옴표(“ ” ‘ ’)는 쓰지 않습니다.
- 모든 문장은 친근한 해요체로 끝냅니다: "~해요", "~이에요/예요", "~했어요", "~할 수 있어요". "~다."로 끝나는 하다체("제안했다", "모델이다")와 반말("~해", "~야")은 쓰지 않습니다. 명사로 끝내지도 않습니다("29.5% 증가."). 예) "정확도를 높였다." 대신 "정확도를 높였어요."
- 명사구 필드(`title_ko`, `kind_ko`, `architecture_ko`, `topic`)와 제목 문구는 문장이 아니므로 해요체로 바꾸지 않고 각자의 형식을 지킵니다.

## 권위와 추측
- 출처 없는 권위를 끌어오지 않습니다: "전문가들은", "업계에서는", "많은 연구자들이", "높은 평가를 받고 있어요". 입력이 출처와 내용을 말하면 그것을 씁니다. 예) "전문가들은 이 방식을 높이 평가해요" 대신 "공개 일주일 만에 GitHub star 2천 개를 받았어요".
- 지식의 한계를 말한 뒤 추측으로 채우지 않습니다: "자세한 정보는 공개되지 않았지만 아마 ~", "~로 알려져 있어요". 모르면 쓰지 않습니다. 근거가 없는 판정은 코드가 `확인 필요`로 채웁니다. 예) "학습 데이터는 공개되지 않았지만 아마 웹 문서일 거예요" 대신 그 문장을 빼요.
- 입력에 없는 내용을 단정하지 않습니다. 숫자, 모델 이름, 순위는 입력에 있는 것만 씁니다.

## 말투와 문서 자체 언급
- 챗봇 말투를 남기지 않습니다: "도움이 되셨으면 좋겠어요", "궁금한 점이 있으면", "물론이죠", "좋은 질문이에요", "알려 드릴게요". 예) "좋은 질문이에요. 이 모델은 번역을 해요" 대신 "번역 모델이에요".
- 요점 앞에 뜸을 들이지 않습니다: "자,", "그럼", "결론부터 말하면", "솔직히", "핵심은 ~예요", "살펴볼까요", "알아볼까요". 예) "결론부터 말하면 속도가 두 배예요" 대신 "속도가 두 배예요".
- 소제목(`topic`)을 본문 첫 문장에서 되풀이하지 않습니다. 예) 소제목이 "Mixture of Experts"이면 본문을 "Mixture of Experts는 MoE예요" 대신 "입력마다 일부 전문가 층만 골라 계산해요"로 시작합니다.
- 글 자체를 설명하지 않고 내용을 씁니다: "이번 뉴스레터에서는", "아래 표는", "이 글에서는". 예) "이번 뉴스레터에서는 로봇 모델을 소개해요" 대신 "로봇 팔을 움직이는 모델이 두 편 나왔어요".
- 독자가 이미 아는 배경을 다시 설명하는 규칙은 대화 답장용이라 주간 뉴스레터에는 해당하지 않습니다.
